## Objective

A device with two redundant binary sensors should raise a warning exactly when the sensors disagree, which is the XOR function. The lab uses this four-point problem to make a neural network's learning mechanism fully inspectable. The goals were:

- understand why XOR needs a nonlinear hidden layer;
- pair the output activation with the right loss for the task;
- connect PyTorch's `backward()` to hand-derived backpropagation;
- test whether learning is really happening, by checking losses, predictions, gradients and repeated runs;
- demonstrate the symmetry problem caused by identical initialisation;
- compare hidden activations;
- extend the model to a three-class softmax output;
- use an LLM to write the code while keeping responsibility for the specification, verification and interpretation.

## What was built

The code uses PyTorch, NumPy and matplotlib, and runs on the CPU in about a minute.

- **Baselines:** logistic regression and a 609-parameter *deep linear* network. Both converge to $p = 0.5$ everywhere, with loss $\ln 2$.
- **2–2–1 network:** tanh hidden layer, one logit, `BCEWithLogitsLoss`, full-batch SGD. It was generated by an LLM from a written specification, then inspected and corrected before it was run.
- **Gradient checks:** autograd compared against the hand-derived chain rule, against finite differences, and against the mean of per-example gradients.
- **Experiments:**
  - the symmetry experiment: all-zero and all-constant initialisation;
  - the activation experiment: sigmoid, tanh and ReLU, on one seed and over 20 seeds, with a pre-activation diagnostic for saturation vs dead units;
  - the three-class extension: `Linear(2, 3)` with `CrossEntropyLoss`, a $p - y$ gradient check, and softmax shift-invariance and overflow tests.

## Key results

| Experiment | Result |
|---|---|
| Linear / deep linear model | stuck at $p = 0.5$, loss 0.6931 = $\ln 2$, as predicted |
| 2–2–1 tanh, seed 0 | loss 0.715 → 0.0006, all four correct; hidden units learned **OR** and **NAND** |
| 2–2–1 tanh, 20 seeds | solved on only 11 of 20 seeds; the rest are stuck at loss ½ ln 2 |
| Gradient checks | autograd = chain rule = finite differences = mean of per-example gradients (to about $10^{-7}$) |
| Zero initialisation | every gradient exactly 0, so nothing ever moves |
| All-0.5 initialisation | the rows of $W^{(1)}$ move in lock-step, stay identical, and XOR is not solved |
| Activations (seed 0 / 20 seeds) | tanh fastest; sigmoid slow (a 2000-step plateau) but most reliable (15/20); ReLU dies (4/20) |
| LLM's first version | double sigmoid: runs without error, but its loss can't go below 0.503 and it can't solve the task |
| Three-class softmax | all four correct; logit gradient equals $(p - y)/N$ exactly; naive softmax overflows at +100 |

## What I learned

- **Nonlinearity, not depth, is what adds expressive power.** A stack of linear layers is still one linear map. A two-unit nonlinear hidden layer solves XOR by building features (OR, NAND) in which the problem becomes linearly separable.
- **Backpropagation assigns the hidden units their jobs.** They have no targets. The output error, sent backwards through the weights and scaled by $f'(a)$, decides what each unit learns.
- **Symmetry must be broken.** Identical units receive identical gradients forever, so random initialisation is a requirement, not a detail.
- **Activation choice shapes the gradient through $f'(a)$.** Sigmoid scales it by at most 1/4, tanh passes it almost unchanged near 0, and ReLU passes it or blocks it completely (dead units). Which activation works best depends on what is measured and on the setting, so four points cannot justify calling any of them "best".
- **Output layer and loss are one design decision.** Sigmoid goes with BCE and softmax with cross-entropy, because each loss is the negative log-likelihood of its output's probability model, and together they give the clean $p - y$ gradient.
- **One successful run is not evidence.** Minimal networks have local minima (11/20 seeds). Tests should check losses, labels, gradients, representations and repeated runs.
- **LLM code has to be verified against the specification.** The generated code ran without error and its loss went down, yet it could never solve the task. Reading the code against the specification caught the problem before execution.
